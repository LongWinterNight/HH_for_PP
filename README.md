# HH.ru Analytics

[![Python](https://img.shields.io/badge/Python-3.10+-blue.svg)](https://python.org)
[![FastAPI](https://img.shields.io/badge/FastAPI-0.109+-green.svg)](https://fastapi.tiangolo.com)
[![License](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

Система для сбора и анализа вакансий с HH.ru. Парсит вакансии через публичный API, извлекает Hard Skills, Soft Skills и Tools, строит аналитику и формирует отчёты.

Проект сделан, чтобы видеть реальный спрос на навыки по данным, а не по ощущениям. Обработано более 1000 вакансий; подойдёт аналитикам рынка труда, HR и карьерным консультантам.

![Панель управления](docs/screenshot.png)

---

## Возможности

- Сбор вакансий по ключевым словам (59 профессий из коробки)
- 8 KPI метрик: зарплаты, количество вакансий, навыков, компаний, регионов
- Топ-20 навыков по трём категориям: Hard Skills, Soft Skills, Tools
- Фильтры: период, регион, опыт, только с зарплатой
- Экспорт в PDF, Excel, CSV
- Поиск с автодополнением и фильтрами

## Установка

### 1. Клонировать репозиторий

```bash
git clone https://github.com/LongWinterNight/HH_for_PP.git
cd HH_for_PP
```

### 2. Установить зависимости

```bash
pip install -r requirements.txt
```

> Если `pip` не найден — используй `pip3` или `python -m pip install -r requirements.txt`

### 3. Создать файл конфигурации

**Windows:**
```cmd
copy .env.example .env
```

**Linux / macOS:**
```bash
cp .env.example .env
```

### 4. Указать email

Открой файл `.env` в текстовом редакторе и замени значение:

```env
HH_USER_EMAIL=твой_email@example.com
```

Это стандартное требование API HH.ru — email идентифицирует запросы. OAuth-токен не нужен. Данные хранятся только локально на твоём компьютере.

> Можно пропустить этот шаг — email можно ввести прямо в интерфейсе при первом запуске.

### 5. Запустить

```bash
python web/app/main.py
```

Открой в браузере: **http://localhost:8000**

## Первый запуск

1. Если email не был указан в `.env` — появится окно для его ввода. Введи email от аккаунта HH.ru.
2. Перейди в раздел **Сбор данных**.
3. Добавь один-два запроса — или выбери профессию в разделе **Профессии**.
4. Нажми **Запустить сбор** и дождись завершения (прогресс виден в реальном времени).
5. Перейди в **Аналитику** — данные появятся автоматически.

## Как запускать каждый день

Двойной клик по **`run-site.bat`** в корне проекта. Всё.

Пока окно открыто — сайт работает и доступен из интернета. Закрыли окно
или выключили компьютер — доступ пропал: приложение живёт на этом
компьютере, а не на сервере.

| Откуда | Адрес |
|---|---|
| С этого компьютера | http://127.0.0.1:8000 |
| Из вашей сети | адрес печатается в окне при запуске |
| Из интернета | `PUBLIC_URL` из `.env`, если задан |

Вход по логину и паролю из `.env` (`BASIC_AUTH_USER` / `BASIC_AUTH_PASSWORD`) —
браузер спросит их один раз.

Что делает `run-site.bat`, кроме запуска: собирает интерфейс, если сборки
нет, отказывается стартовать без пароля и делает копию базы в
`data/backups/` (хранит десять последних).

Правки в коде подхватываются сами — перезапускать вручную не нужно. Но
не в любой момент: пока идёт сбор данных или пока кто-то щёлкает по
сайту, перезапуск откладывается. Сбор живёт внутри того же процесса, и
обрывать его ради правки нельзя; в окне видно, чего ждёт перезапуск. Подробности и что делать,
если адрес перестал открываться, — в [docs/access-for-testing.md](docs/access-for-testing.md).

## Сбор по расписанию

Сбор может идти сам, без открытого приложения. Запуск по времени делает планировщик Windows; задание запускает тот же сбор, что кнопка на экране, по запросам из списка на экране «Сбор данных».

```bash
python scripts/расписание.py --установить --время 03:30   # каждый день в 03:30
python scripts/расписание.py --состояние                  # что обещано и выполняется ли
python scripts/расписание.py --снять
python scripts/собрать.py --проверить                     # что будет собрано, без сбора
```

- Сбор по расписанию только дописывает к базе; перед ним снимается её копия в `data/backups/`, хранятся три последние.
- Пропущенный запуск догоняется, когда компьютер включат. Задание идёт от имени вошедшего пользователя — без входа в систему оно не запускается.
- Отказ сбора уходит в журнал и оповещения, как у сбора с экрана. Если сбор не запустился вовсе, об этом скажет экран «Сбор данных» и оповещение при следующем старте приложения.
- Сбор по расписанию виден на экране, пока идёт, и его можно остановить оттуда же.

## Как устроено

Экран «Как устроено» показывает, что происходит в продукте, на живых
числах: путь вакансии от источника до списка, поиск по шагам на любом
запросе (как разобран запрос, что нашли слова, что нашёл смысл, как
списки слились) и цепочку, по которой отказ сбора доходит до журнала,
шапки и оповещения. Пока идёт сбор, по схеме идёт поток; объясняющие
анимации проигрываются по кнопке.

## Поиск

Поле поиска на экране «Вакансии» принимает профессию, навык или
описание задачи словами и ищет двумя способами сразу.

**По словам** — с учётом словоформ («дизайнера» находит «дизайнер»),
синонимов из словаря навыков («3д макс» находит «3ds Max» и «3dsmax»),
опечаток («проэктировщик») и латинских названий, записанных кириллицей
(«фигма»). Что именно поиск исправил в запросе, написано под фильтрами.

**По смыслу** — локальной моделью на видеокарте: «питон разработчик»
находит вакансии Python-разработчиков, в которых слова «питон» нет.
Тексты вакансий при этом никуда не уходят. Модель необязательна: без
неё, без видеокарты или с `SEARCH_VECTORS=0` поиск работает на словах.

Списки сливаются по местам, порядок выдачи — по соответствию запросу;
в строке подписано, где вакансия найдена.

```
pip install -r requirements-search.txt        # библиотеки для модели
python scripts/построить_поиск.py --скачать   # модель, 2,2 ГБ, один раз
python scripts/построить_поиск.py             # индексы по всей базе
```

Сбор дописывает новые вакансии в индексы сам. Качество меряется на
эталоне из 18 запросов и 519 размеченных пар:
`python scripts/maintenance/эталон_поиска.py --замер`.

## Журнал и оповещения

**Журнал работы** пишется в `logs/` — файл на день, хранится 30 дней.
В нём всё, что приложение печатает в окно, и трассировки сбоев. Пароль
и токены из `.env` в журнал не попадают: их значения заменяются при
записи.

**Отказ сбора** виден в шапке на любом экране — метка «Сбор не удался»
ведёт на «Сбор данных», где причина объяснена. Исход читается из базы,
поэтому перезапуск приложения его не стирает.

**Оповещение в Telegram** приходит при отказе сбора, при обрыве сбора
перезапуском и когда сбор прошёл не целиком. Включается двумя строками
в `.env`; как их получить и как проверить, что сообщение дойдёт:

```
python scripts/проверить_оповещение.py            # пробное сообщение
python scripts/проверить_оповещение.py --журнал   # последние оповещения и их исход
```

Каждое оповещение записывается в `logs/оповещения.jsonl` вместе с тем,
дошло ли оно. Канал, который не настроен, там так и назван — молча
оповещения не пропадают.

## Устранение проблем

### `ModuleNotFoundError`

```bash
pip install -r requirements.txt
```

### Порт 8000 занят

**Windows:**
```cmd
netstat -ano | findstr :8000
taskkill /F /PID <PID>
```

**Linux / macOS:**
```bash
kill -9 $(lsof -t -i:8000)
```

### Парсер возвращает 403

HH.ru временно блокирует IP при слишком частых запросах — это защита от DDoS.  
Подожди 1–2 часа и попробуй снова. Если используешь VPN или прокси — попробуй отключить.

### Данные не отображаются

Убедись что парсер завершил работу и нашёл хотя бы несколько вакансий. Проверь консоль на ошибки.
