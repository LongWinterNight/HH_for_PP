# BaseVacancy · карта фронтенда

Документ фиксирует, где что лежит и почему именно там. Правило одно: у файла есть единственное место, и оно выводится из роли файла, а не из истории. Новый файл, которому не находится места в этом дереве, — повод дополнить документ, а не положить рядом.

Основание: `design/brief/` (дизайн-система, 27 страниц + `tokens.css`), конспект — `design/spec/`.

## Решения, из которых следует дерево

**Шрифты только локальные.** `@fontsource-variable/geologica` и `@fontsource/martian-mono` ставятся npm-зависимостями, `woff2` попадают в сборку и раздаются с нашего домена. Ни одного внешнего запроса: интерфейс одинаков офлайн, в закрытом контуре и при недоступном Google Fonts.

**Ни `base.css`, ни `print.css`.** `tokens.css` из дизайн-системы содержит не только слоты, но и базовые правила вместе с блоком печати. Отдельный файл с теми же правилами стал бы вторым источником истины, а расхождение между ними обнаружилось бы на бумаге, где его труднее всего заметить.

**Отдельный `touch.css`.** Высоты управления в дизайн-системе — 40 / 32 / 28, они рассчитаны на курсор, а чек-лист требует 44px на касании. Правила собраны в один файл под `@media (pointer: coarse)`: иначе этот медиазапрос пришлось бы повторить в пятнадцати компонентах, и один из них рано или поздно забыли бы. Условие — именно грубый указатель, а не ширина экрана: планшет шириной 1024 — это палец.

**`utils/`, а не `lib/`.** В `.gitignore` проекта есть строка `lib/` для Python-сборок — папка `src/lib/` молча не попала бы в репозиторий.

**Три уровня компонентов.** `ui/` не знает про вакансии, `domain/` не знает про экран, `views/` собирает. Правило проверяется одним вопросом: можно ли перенести файл в другой продукт, ничего не переписав.

**Один источник вида статуса.** `BvStatus.vue` — единственное место, где статусы получают цвет и форму. Дизайн-система прямо запрещает рисовать их заново на каждом экране.

**Графики не красятся на месте.** Любой цвет графика приходит из `utils/chartTheme.js`. Кольцевых диаграмм в системе нет: доли целого — составная полоса, категории — горизонтальные полосы.

## Сборка и раздача

- Разработка: `npm run dev` в `frontend/` (Vite на 5173, `/api` проксируется на `http://localhost:8000`), бэкенд поднимается как раньше.
- Продукт: `npm run build` кладёт результат в `frontend/dist`, FastAPI отдаёт его как статику и возвращает `index.html` на все не-API маршруты.
- Docker: сборка двухэтапная — `node:22-alpine` собирает фронтенд, `dist` копируется в питоновский образ. Node в финальный образ не попадает.
- Маршруты интерфейса (`/vacancies`, `/reports`, …) отдаёт `index.html`: обработчик `spa_routes` объявлен последним в `web/app/main.py`, иначе он перехватывал бы вызовы API.
